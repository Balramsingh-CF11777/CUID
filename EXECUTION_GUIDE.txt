CUID SYNC EXECUTION GUIDE
=========================

Run all commands from the project folder:

    /Users/balramsl/Documents/Latest Development/cuid_sync_scripts

Each job uses the .env file inside its own folder. Do not run the scripts
from a different folder.


1. BEFORE YOU START
-------------------

Check which jobs are on, and the last result of each:

    python run_all.py --list

All 18 jobs start as enabled. Vendor Master runs after CoApplicant and Guarantor.

The gap between jobs is 20 seconds. Change it for one run with --interval.
Example for 2 minutes:

    python run_all.py --interval 120

To start the next job immediately:

    python run_all.py --interval 0


2. TURN JOBS ON OR OFF
----------------------

These commands only update jobs.json. They do not start the sync.

One job:

    python run_all.py --disable posidex
    python run_all.py --enable posidex

Two or more jobs (comma, no spaces required):

    python run_all.py --disable posidex,sme_los,vf_leap
    python run_all.py --enable posidex,sme_los,vf_leap

Or repeat the flag:

    python run_all.py --disable posidex --disable sme_los

You can also open jobs.json and set "enabled" to true or false.

Confirm before the run:

    python run_all.py --list

Disabled jobs are skipped by a full run and by --resume.


3. RUN IN THREE BATCHES
-----------------------

Run batch 1 first, then batch 2, then batch 3.
Each script runs only the jobs in that batch, in the order below.
The wait between jobs is 20 seconds.

    ./run_batch1.sh
    ./run_batch2.sh
    ./run_batch3.sh

120 seconds between jobs in that batch:

    ./run_batch1.sh --interval 120

    python run_all.py --only dealer_vf,hl_agent,lap_agent,vf_leap
    python run_all.py --only cd_samsung_los,csel_d2c,csel_zoho,gold_loan,hl_falcon,lap_los,sbpl_los,sme_los,coapplicant_guarantor,vendor_master

--only follows the order of the ids you type.
If one job in a batch fails, it is recorded and the later jobs in that batch still run.

4. FULL RUN OF EVERY ENABLED JOB
--------------------------------

    python run_all.py

What happens:

- Enabled jobs run one after another, in the order in section 8.
- Each script starts inside its own folder.
- If one job fails, it is recorded and the remaining jobs still run.
- Screen output is also saved to logs/<job_id>.log
- The result of each job is saved to run_state.json


5. IF ONE JOB FAILS
-------------------

1) Note the failed id from the summary, or run:

    python run_all.py --list

2) Fix that job, then run it alone. This runs it even if it is disabled:

    python run_all.py --only posidex

Several jobs:

    python run_all.py --only posidex,sme_los

3) Continue the rest. Jobs that already succeeded are skipped.
   Failed jobs and jobs that were stopped halfway run again.
   Disabled jobs stay skipped.

    python run_all.py --resume


6. START OVER
-------------

Clear the saved results. This does not start the sync.

    python run_all.py --reset

Then run again:

    python run_all.py


7. WHERE TO LOOK AFTER A RUN
----------------------------

    python run_all.py --list     status of every job
    logs/<job_id>.log            output of that job's latest run
    run_state.json               exit code and start/finish time

Status values:

    success     finished with exit code 0
    failed      finished with an error, or was interrupted
    running     started and did not finish (treat as failed; --resume will rerun it)
    -           not run yet in this state file
